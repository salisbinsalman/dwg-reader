DWG File Concepts
Objects
Total count of everything stored in the file — entities, block definitions, layers, text styles, linetypes, app ID registrations, XDATA records. A healthy Valmet P&ID: 5,000–20,000. GOR: ~7,000–8,000. KSD: ~60–2,000.
Entities
Drawable elements in model space only: lines, circles, arcs, text, polylines, and block inserts (placed symbols). Excludes definitions and metadata.
Blocks
Reusable symbol definitions — the library. E.g. one block definition VENTK defines a ball valve symbol. Definitions count is how many unique symbols are defined.
Block Inserts
Each placement of a block on the drawing. VENTK ×42 means 42 ball valves placed. Count × block name = equipment tally.
Attr Tags
Structured data fields attached to a block insert — like form fields on a symbol. Tag = field name (e.g. VEPOSITIO), value = the data (e.g. 35-26-FV-001). Valmet: ~1,800 per drawing. GOR: ~1 per drawing. KSD: ~270.
Layers
Named organisational groups for entities. Layer name encodes equipment type or medium: Valmet uses P-WATER, P-STEAM2; GOR uses 1-AIR GOR, 1-TAG AND INSTRUMENTS GOR; KSD uses PS, BLANKETT.
XDATA
Extended Entity Data — custom structured data attached to any entity by a registered app. Valmet's PCAD-POS-INFO XDATA stores instrument type, area code, position ID, and description on each instrument bubble. LIN_FROM / LIN_TO XDATA on pipe polylines encodes connectivity.
App IDs
Software registration keys for XDATA. Which app IDs are registered is the primary ecosystem fingerprint: PCAD_ = Valmet · IDOK_ = GOR · GENIUS_ only = KSD.

Connectivity — How Pipe Topology Is Encoded
Connectivity determines whether the P&ID flow graph can be reconstructed automatically or requires spatial geometry analysis.
LIN_FROM / LIN_TO (Valmet PS-21 only) Named endpoints stored as PCAD_ XDATA on each pipe polyline. Every pipe segment knows exactly what it connects from and to. Enables full automated P&ID graph reconstruction — no geometry analysis needed. Record count shown in brackets.
XDATA present, no named endpoints Custom app data exists on entities (GENIUS_, IDOK_) but no LIN_FROM/LIN_TO schema. Connectivity cannot be read directly — requires inspection of specific app ID schemas. Applies to most GOR and some KSD drawings.
No semantic connectivity Pipe routing is LWPOLYLINE geometry only. Connectivity must be inferred from spatial proximity of polyline endpoints (geometric tracing). KSD cross-sheet refs are encoded in BENÄMNING attribute text (e.g. KSDM160104103 sh.03).
Parse failed — no entity data ODA File Converter produced malformed DXF output (DXFStructureError: missing ENDSEC tag). Affects 15 of 25 KSD DWGs. Only CSV-level metadata is available. Requires alternative parser (LibreDWG) or PDF fallback.

03 Recommended Architecture (Summary)
Universal ingestion → Ecosystem detector → Three standard-specific adapters → Common entity model → SAP mapper.

A single universal parser will not work across all three families. The ingestion layer (ODA + ezdxf) is already built. The three adapters and the SAP mapping layer are the primary R&D deliverables.
04 How We Identified Each Standard — Reasoning & Sources
Where the standard names came from
🇫🇮 "Valmet PS-21" / "SML Standard 21"

The name "PS-21" comes from the Shotton Mill Ltd internal document numbering system. Two standard PDFs were found in resources/Naming Standards/Naming _PM3/:
 · RAU4EG1432.03 — "Common for Mill, Mechanical, Process and Automation"
 · RAU4EG1433.04 — "Process and Automation" (authored by Hannu Mölsä, Valmet)

These documents specify position code format MM-SSYYY-XXX (e.g. 35-24P529), instrument type letters (FC, TC, LC, PI, TI…), motor suffix rules (-M1, -M2), and area numbering — all of which match values observed in the PCAD-POS-INFO XDATA and block attributes of the 35 Valmet DWGs.

The "PCAD_" prefix in AutoCAD App IDs stands for Plant CAD — Valmet's proprietary P&ID authoring software. These IDs are only registered by Valmet's software; no other engineering company uses them.
🇮🇹 "GOR Italian" / "GOR S.r.l."

The name "GOR" comes directly from the filename prefix — every tissue machine P&ID from this vendor begins with GORA* or GORB* (19 DWGs). The username gorceschma recorded in each DWG header reinforces the same company abbreviation.

GOR S.r.l. is an Italian engineering firm specialising in tissue machine P&IDs. We confirmed the Italian origin by the layer and block names — Italian vocabulary: cartiglio (title cartouche), nascosta (hidden line), revisioni (revisions), squadratura (drawing border).

No standard document was provided by GOR. The block/layer classification in this report was entirely reverse-engineered from the DWG data in outputs/dwg_per_file_inventory.json. The 4 GOR linetype names (COMPRESS_AIR_GOR, BACK_PRESSURE_GOR, GAS_LINE, 1-AIR GOR) were read directly from the DXF linetype table.
🇸🇪 "KSD Swedish" / "KSD / Andritz"

The name "KSD" and the standard reference both come from the filename itself — every drawing is named KSDM160104*.dwg, where KSDM160104 is the document number of the KSD Process Numbering Standard.

The full standard PDF was found in resources/Naming Standards/Naming_Tissue/Tissue KSDM160104_010.00 Process Numbering System.pdf (21 pages). It explicitly documents:
 · Equipment tag format xyyz-aaa (e.g. 122E-001 = area 122, type E, serial 001)
 · Valve numbering 126V-001, motor suffix -M1/-M2
 · KRETS (circuit/loop tag) + POSNR (position number) attribute naming
 · Pipeline format 136L-001 (area 136, type L = line)

The username ksdwenzhec in the DWG header and Swedish vocabulary in layer/block names (blankett=form, krets=circuit, benämning=description, revhuvud=revision header) confirms the Swedish origin. KSD supplied drawings were later integrated into the Andritz delivery scope for the tissue machine.

Where block and attribute tag knowledge came from
Block / TagKnowledge sourceHow we verified
P7A*, PPI_* → Instrument DWG observation — every instance carries PCAD-POS-INFO XDATA with field [1] = instrument type code (LT, LC, FI, TI, PI…). Reverse-engineered from outputs/dwg_per_file_inventory.json. Instrument type codes (LT, LC, FI…) match the type letter table in RAU4EG1433.04 §3 (PS-21 standard PDF).
VENTK, TOIMILV, TAKAISKU, VAROV → Valve Finnish vocabulary: venttiili = valve, toimilaiteventtiili = actuated valve, takaisku = check valve, varoventtiili = safety valve. Cross-referenced with Finnish engineering dictionaries. Every insert of these blocks carries VEPOSITIO (position tag), VENIMI (name), VEKEMIKAALI (medium) attributes — consistent with valve record fields in SAP. Observed across all 35 Valmet DWGs.
LINJA, VEPOSITIO, VENIMI attrs → Pipeline / Valve fields Finnish vocabulary: linja = line, positio = position, nimi = name. PS-21 standard PDF (RAU4EG1433.04) documents position code format and cross-sheet line references. Sample values match PS-21 format: LINJA=35-26, VEPOSITIO=35-24FV-001.
KRETS, POSNR, BENÄMNING attrs → KSD fields KSD standard PDF (KSDM160104_010.00, resources/Naming Standards/Naming_Tissue/) — explicitly names KRETS (circuit tag), POSNR (position number), and BENÄMNING (description) as the primary instrument tagging fields. Sample values in DWGs match: KRETS=126LC (area 126, type Level Control), POSNR=001.
CARTIGLIO, LOOPDCS, GOR layers → GOR Italian vocabulary: cartiglio = title cartouche. No standard document. Classification is purely by exclusion — these blocks appear in all 19 GOR DWGs and in zero Valmet/KSD DWGs. Cross-file check in dwg_per_file_inventory.json: CARTIGLIO block present in 100% of GORA*/GORB*, absent in 100% of PCSG*/KSDM*.
LIN_FROM / LIN_TO → Pipe connectivity PCAD XDATA inspection — reading raw XDATA attached to LWPOLYLINE entities in Valmet DWGs revealed app ID GENIUS_PCAD-LIN with string pairs matching known tag IDs. Fully reverse-engineered from DWG data; not documented in PS-21 PDFs. Graph reconstruction produces consistent pipe networks with correct instrument-to-pipe connections. Validated against manually readable P&ID drawings.
GOR linetype names → pipe medium DXF LTYPE table — linetype names like COMPRESS_AIR_GOR, BACK_PRESSURE_GOR, GAS_LINE are stored verbatim in the DXF file and read directly. No standard document needed — the names are self-describing in English. Visual comparison with GOR P&ID drawings confirms linetype visual pattern matches the medium label.

§V Project Vocabulary — Quick Reference

One-liner definitions for every term used across this assessment. Hover a term for its full context.

SAP Concepts
FLOCFunctional Location — SAP's hierarchical address for a physical place in a plant (e.g. 5001-PM3-PRESS-SEC1). Every piece of equipment is hung under a FLOC.
EquipmentSAP Equipment — a maintainable physical asset (pump, valve, motor) with its own SAP record, serial number, and maintenance history.
PlantTop-level SAP org unit. Shotton Mill = Plant 5001. All FLOCs and equipment belong to a plant.
Object TypeSAP Equipment category code (e.g. M = Motor, P = Pump). Controls which fields and maintenance plans apply. Defined in sml_object_types.json.
SAP MaskA template that enforces a fixed naming format for FLOCs or equipment — e.g. ####-AAA-BBB where each segment is validated. Determines how many levels the hierarchy has.
Functional Location StructureThe allowed FLOC depth levels: Plant → Line → Process → Sub-process → Equipment group → Equipment. Each level is a node in the hierarchy tree.
Sub-process (BR level)The third or fourth level of the FLOC tree at Shotton — groups equipment into operating areas (e.g. BR1, BR2, BR3 at Tissue Machine).
SAP Import FileA flat CSV/XLSX that the SAP data loader reads to create or update FLOCs and Equipment records in bulk. Column order and field names must match exactly.
Short Text / DescriptionThe 40-char equipment description field in SAP — the main human-readable name. Must follow abbreviation rules (see sml_abbreviations.json).
Long TextFree-text notes field in SAP Equipment, not length-constrained. Used for extra technical data not fitting the short-text limit.
Parent–ChildFLOC relationship: a child FLOC's code starts with its parent's code. Equipment records point to their parent FLOC. Load order matters — parents must exist before children.
DWG / CAD Concepts
DWGAutoCAD's proprietary binary drawing format (.dwg). The source files we're reading. Not directly human-readable — must be converted to DXF first.
DXFDrawing Exchange Format — a text/binary format AutoCAD uses to export drawing data. We convert DWG → DXF using ODA File Converter, then parse with ezdxf.
EntityAny single drawable object in a DWG: a LINE, ARC, TEXT, INSERT (block reference), LWPOLYLINE, etc. Model space holds all the actual drawing entities.
BlockA named, reusable symbol definition — e.g. VENTK (valve symbol). Defined once in the block table, then stamped into model space as INSERTs many times.
INSERTA block reference entity — one occurrence of a block stamped at a specific position, rotation, and scale. A drawing can have 3000 INSERTs of 50 block definitions.
Attribute / ATTRIBA text field attached to a block INSERT that carries data — e.g. VEPOSITIO = "101-XV-001". Attributes are how instrument tags, valve IDs, and descriptions are stored on symbols.
Attribute TagThe field name of an attribute — e.g. VEPOSITIO, VENIMI, KRETS. The tag is always uppercase in DXF. The value is what the draughtsman typed.
XDATAExtended Entity Data — structured data that a CAD application attaches to any entity, keyed by App ID. Valmet stores instrument type codes and area codes in PCAD-POS-INFO XDATA.
EEDExtended Entity Data — same as XDATA. Different name used in some ezdxf documentation.
App IDA registered application identifier that namespaces XDATA — e.g. PCAD (Valmet), IDOK (GOR), GENIUS (KSD). Presence of an App ID fingerprints the CAD ecosystem.
LayerA named grouping for entities — like a transparent sheet overlay. Used to separate pipelines, instruments, annotations, etc. Layer names follow CAD standards (e.g. VENTTIILI = valves).
Model SpaceThe main drawing canvas in a DWG — where all the actual P&ID content lives. Distinct from Paper Space (which holds print layout frames).
Paper SpaceThe print layout area of a DWG — contains title block, borders, and viewports into model space. We ignore paper space for data extraction.
Title BlockA border block at the edge of the drawing that holds document metadata: project name, drawing number, revision, date. Typically a single INSERT with many attributes.
LinetypeThe dash/dot pattern of a line — e.g. continuous, dashed, centre. Custom linetypes can signal pipeline types (process, utility, steam, etc.).
ODA File ConverterOpen Design Alliance tool that converts proprietary DWG files to open DXF format. Required first step before ezdxf can read the files.
ezdxfPython library for reading and writing DXF files. Our main parsing engine after ODA conversion. Fails on malformed DXF (e.g. KSD files with missing ENDSEC tag).
LIN_FROM / LIN_TOXDATA fields on pipe polylines in Valmet drawings that encode direct connectivity — which block INSERT a pipe segment starts and ends at. Gives us a real topology graph.
DXFStructureErrorezdxf parse error meaning the DXF is structurally invalid. KSD DWGs trigger this with "missing ENDSEC tag" — ~15 of 25 KSD files affected. Root cause undiagnosed.
P&ID / Engineering
P&IDPiping and Instrumentation Diagram — an engineering schematic showing process equipment, pipes, and instrumentation with their interconnections and control loops.
Instrument TagA unique alphanumeric ID for an instrument — e.g. 101-FI-001 (area 101, Flow Indicator, #001). Format follows the applicable naming standard (PS-21, KSD, etc.).
Instrument BubbleThe circle symbol on a P&ID that represents an instrument. In Valmet DWGs these are PPI_* blocks; in KSD they're identified by KRETS attribute.
Position TagThe equipment or valve tag used for identification on the P&ID — stored in VEPOSITIO (Valmet) or POSNR (KSD). Becomes the SAP Equipment tag.
LoopA control loop: a set of instruments (sensor, controller, actuator) that maintain a process variable. Instruments in a loop share the same loop number in their tag.
Process MediumThe fluid or material flowing through a pipe — water, steam, pulp, chemicals. Stored in VEKEMIKAALI (Finnish: chemical) attribute on valve blocks.
DN / PNPipe Diameter Nominal (size in mm) and Pressure Nominal (pressure rating in bar). Stored in PUTDN / PUTPN attributes on pipe blocks.
Cross-sheet ReferenceA symbol indicating that a pipe or signal continues on another drawing. In Valmet: NUOLI (arrow) blocks with KAAVIO (drawing number) attribute.
Ecosystems & Standards
EcosystemOur term for a cluster of DWGs produced by the same CAD software and naming standard — identified by App ID fingerprint. Three at Shotton: Valmet PS-21, GOR Italian, KSD Swedish.
Valmet PS-21Finnish process CAD software by Valmet. Produces DWGs with PCAD_* App IDs. Follows PS-21 naming standard (RAU4EG1432 + RAU4EG1433). 35 DWGs at Shotton.
PS-21Valmet's internal CAD naming standard — documents RAU4EG1432.03 (Common for Mill) and RAU4EG1433.04 (Process & Automation). Defines block names, attribute tags, and position tag format.
PCADValmet's proprietary CAD application identifier. Presence of PCAD_* App IDs in a DWG's XDATA is the primary fingerprint for the Valmet PS-21 ecosystem.
GOR ItalianItalian P&ID CAD software. Produces DWGs with IDOK_* App IDs. No named standard found — block names and tags are in Italian. 19 DWGs at Shotton (GORA*/GORB* prefix).
IDOKGOR's CAD application identifier. Presence of IDOK_* App IDs fingerprints the GOR ecosystem. GOR stores data in TEXT entities rather than block attributes.
KSD SwedishSwedish P&ID CAD software (related to Andritz/Metso). Produces DWGs with GENIUS_* App IDs. Follows KSDM160104_010.00 standard. 25 DWGs at Shotton (KSDM* prefix).
GENIUSKSD/Andritz CAD application identifier. Presence of GENIUS_* App IDs fingerprints the KSD ecosystem. Also used by Metso software family.
KSDM160104_010.00KSD's process numbering standard PDF (21 pages). Defines tag format xyyz-aaa (e.g. 126A-001), primary fields KRETS/POSNR/BENÄMNING, and area code grid. Partially parsed into tissue_ksdm160104.json.
RAU4EG1432 / RAU4EG1433The two PS-21 standard PDFs found in resources. RAU4EG1432.03 = Common for Mill (plant-wide rules). RAU4EG1433.04 = Process and Automation (instrument-specific rules, §3 defines type codes).
BENÄMNINGSwedish: "designation / name". The primary description attribute in KSD drawings. Maps to the SAP Equipment short-text description field.
VENIMIFinnish: "valve name". The description attribute on Valmet valve blocks — e.g. LÄPPÄVENTTIILI (butterfly valve). Maps to SAP Equipment description.
KRETSSwedish: "circuit / loop". The instrument loop/tag field in KSD drawings — equivalent to the instrument tag number. Primary key for identifying instruments in the KSD ecosystem.
VEPOSITIOFinnish: "valve position". The position tag attribute on Valmet valve and equipment blocks — the primary unique identifier used to match an equipment record in SAP.
